# Проект - анализ пульсовых волн


## 0. Цель проекта и образ результата


Мы разрабатываем прибор, который записывает сигнал фотоплетизмограммы (ФПГ) с пальца руки и пальца стопы.

Мне необходимо выделять отдельные пульсовые волны, оценивать их формы и амплитуды, разрабатывать различные индексы.
Одна из первых задач - это разметить эти пульсовые волны.

Необходимо выбрать метод разметки пульсовых волн, устойчивый к возможному затуханию сигнала и шуму на стопе. 

Задачи хранятся в соответствующей директории (`tasks/task_N.md`). 

Если пользователь просит решить задачу, сначала прочитай файл соответствующей задачи.

Всё, что порождает прогон по задаче, должно лежать в папке прогона `runs/tN-wX-rY/`. 


## 1. Критерий готовности


Прогон закончен, когда команда из раздела «Критерий готовности» задачи
срабатывает без ошибок. Вызови её сам перед окончательным ответом. 
Ответ без пройденной проверки не принимается.

Если в ходе задачи ты пишешь собственные проверки, они дополняют эту 
команду, но не заменяют её.

Если в задаче нет раздела «Критерий готовности» или команда не запускается 
- остановись и спроси пользователя.


## 2. Карта проекта и источники


- Подробная карта проекта лежит в `INDEX.md`
- Перед выполнением задачи изучай карту проекта и, при необходимости,
  необходимые для решения задачи файлы (не противоречащие заданию)
- При изменении карты проекта сам внеси в неё изменения согласно 
  структуре `INDEX.md`


## 3. Инструменты и границы


- Код для выполнения расчётов, расчёты, отчёты в папку `runs/<папка прогона>`, по контексту задания
- Код на Python. Запускать только через `.venv\Scripts\python`.
- Установлены: numpy, scipy, pandas, matplotlib, pytest, neurokit2 (версии — в requirements.txt).
- Новые знания сохраняются в папку `notes/`
- Формат окончаний строк - CRLF


## 4. Запрещено

- Не изменяй файлы в `data/` и `tasks/`.
- Не читай `REPORT.md` - это мой файл, с которым я работаю, куда пишу свои наблюдения по проекту
- Не читай и не выводи содержимое `.env` и других файлов с ключами
- Не копируй записи пациентов в директории вне .gitignore.
- Не выполняй `git push`, удаление файлов и установку пакетов без подтверждения.


## 5. Протокол работы


Режим: ReAct — шаг, проверка результата, следующий шаг.


## 6. Память


После каждой задачи делай запись в `DIARY.md`: дата, запрос, что сделано,результат, точка проверки, итог проверки. Коротко в 2-3 абзаца.


## 7. Остановки


- Три неудачи проверки подряд по одной причине — стоп и отчёт.
- Бюджет одной задачи - 3 000 000 токенов (выходных). При достижении - остановись, сделай отчёт, уточни, продолжать ли.
