# Контракт синтетического набора T1

## Назначение

Фиксирует, что именно обязан выдать `modulator.py`, чтобы результат можно было принять без чтения его кода. Проверка `[[checks/check_1.py]]` реализует только этот контракт; всё, что в него не входит, — свобода реализации.

Версия контракта: 1 (2026-10-21).

## Запуск

```text
python modulator.py --out DIR --all
python modulator.py --out DIR --preset NAME [--preset-name NAME] [--seed N]
```

- `--all` создаёт `DIR/set_<preset>/` для каждого пресета; пресетов не меньше трёх.
- `--preset NAME` создаёт `DIR/<NAME или --preset-name>/`.
- `--seed N` полностью определяет выход: два запуска с одним seed дают побайтово одинаковые файлы, с разными — разные сигналы.
- Каталоги наборов содержат ровно три файла: `signal.csv`, `reference.csv`, `params.json`.

## signal.csv

- Заголовок ровно `t,hand,foot`, разделитель — запятая, десятичная точка.
- `t` — время, с; строго возрастает; `fs = 320` Гц — та же частота, что у прибора (`data/signals.md`); число строк `N = round(duration_s * fs)`.
- `hand`, `foot` — целые отсчёты АЦП в диапазоне 0…65535, без насыщения.
- `hand` — палец руки, `foot` — палец стопы. Оба канала — сумма DC, медленного дрейфа, пульсовых волн и независимого белого шума.

## reference.csv

Столбцы ровно в этом порядке:

| столбец | смысл | единица |
|---|---|---|
| `beat_id` | номер сердечного цикла, 0…n−1 без пропусков | шт. |
| `onset_s` | начало волны руки: уровень пульсовой составляющей равен нулю, дальше идёт подъём | с |
| `peak_s` | момент максимума волны руки | с |
| `peak_foot_s` | номинальный момент максимума волны стопы | с |
| `amp_hand` | высота волны руки над уровнем в `onset_s` | отсчёты АЦП |
| `amp_foot` | номинальная высота волны стопы над её уровнем в начале | отсчёты АЦП |
| `missed_hand` | 1 — волна руки в этом цикле не сгенерирована | 0/1 |
| `missed_foot` | 1 — волна стопы в этом цикле не сгенерирована | 0/1 |
| `foot_gain` | `amp_foot / amp_hand`, при `missed_foot` — 0 | безразмерный |

Правила:

- Одна строка на сердечный цикл, включая пропущенные: `onset_s`, `peak_s`, `peak_foot_s` и обе амплитуды — номинальные, то есть «какими были бы», и определены даже при `missed_* = 1`.
- `onset_s < peak_s < peak_foot_s` в каждой строке.
- `amp_hand`, `amp_foot > 0`; `foot_gain = amp_foot / amp_hand` с точностью до округления.
- `peak_s − onset_s` — время подъёма руки, `peak_foot_s − onset_s − foot_delay_s` — время подъёма стопы.

## params.json

```json
{"preset": "<имя>", "config": {...}}
```

Обязательные ключи `config` (все измеряемы по файлам набора):

| ключ | смысл | единица |
|---|---|---|
| `name` | имя набора | — |
| `seed` | seed генератора | — |
| `fs` | частота дискретизации, 320 | Гц |
| `duration_s` | длительность | с |
| `hr_bpm` | средняя ЧСС | уд/мин |
| `hr_variability` | относительная вариабельность IBI (стандартное отклонение / среднее) | безразмерная |
| `dc_hand`, `dc_foot` | уровень DC | отсчёты АЦП |
| `drift_hand`, `drift_foot` | амплитуда медленного дрейфа | отсчёты АЦП |
| `noise_hand`, `noise_foot` | СКО белого шума | отсчёты АЦП |
| `amp_hand` | базовая амплитуда волны руки | отсчёты АЦП |
| `foot_delay_s` | задержка прихода волны на стопу | с |
| `rise_hand_s`, `rise_foot_s` | время от начала волны до её пика | с |
| `foot_gain` | базовый коэффициент передачи стопы | безразмерный |
| `n_attenuation` | число эпизодов затухания | шт. |
| `attenuation_depth` | минимальный коэффициент передачи стопы в эпизоде, доля от базового усиления | безразмерная, 0…1 |
| `n_missed_hand`, `n_missed_foot` | число пропущенных волн по каналам | шт. |

Дополнительные ключи разрешены: проверка не имеет права требовать внутренних параметров формы (ширина ядра, коэффициент отражённой волны и т. п.).

## Семантические инварианты

1. Один сердечный цикл — одна строка разметки; оба канала относятся к одному и тому же циклу.
2. Волна стопы — затухающая и запаздывающая копия волны руки: `peak_foot_s > peak_s`, `rise_foot_s > rise_hand_s`, `amp_foot < amp_hand`, шум стопы не меньше шума руки. Связь затухания и задержки — `[[Тезис — На стопе пульс затухает и запаздывает]]`.
3. Пропуск — отсутствие волны только в своём канале; второй канал в этом цикле не меняется.
4. `foot_gain` — множитель к амплитуде руки плюс эпизоды затухания; амплитуда стопы следует ему с точностью до шума. `attenuation_depth` — это минимум коэффициента, а не «доля среза»: при `depth = 0.4` сигнал падает до 40 % базового усиления.
5. Дрейф — медленный (ниже 0.5 Гц) и по модулю меньше амплитуды волны руки.

## Покрытие сценариев

Среди наборов прогона обязательны:

- чистый: без пропусков, без затухания, шум стопы не более чем в 1.3 раза выше шума руки;
- с дрейфом и шумом;
- с пропусками в обоих каналах;
- с эпизодами затухания (`n_attenuation > 0`, `0 < attenuation_depth <= 0.6`);
- с шумной стопой (`noise_foot >= 1.2 * noise_hand`).

Один набор может закрывать несколько пунктов, но наборов должно быть не меньше трёх. Каждый набор — не короче 120 с и не меньше 150 ударов: на меньшем числе p99 и корреляция амплитуд неустойчивы.

## Что контракт не задаёт

Форму ядра волны, число отражённых компонент, модель дыхательной модуляции, конкретный генератор дрейфа, распределение пропусков. Это пространство для следующей версии модулятора — см. `[[Метод — модель волны следующей версии]]`.
